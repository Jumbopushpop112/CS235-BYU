1) Bubble Sort

🔹 Idea
Repeatedly swap adjacent elements if they are in the wrong order.
Large elements “bubble” to the end after each pass.

🔹 Pseudocode

procedure bubbleSort(arr):
    n = length(arr)

    for i = 0 to n-2:
        for j = 0 to n-2-i:
            if arr[j] > arr[j+1]:
                swap arr[j] and arr[j+1]

🔹 Explanation

Compare neighboring elements.

Swap if they are out of order.

After each outer loop, the largest unsorted element moves to its correct position.

🔹 Best Case: O(n)

When the array is already sorted (with swap-check optimization).

Only one pass is needed.

🔹 Worst Case: O(n²)

When the array is reverse sorted.

Maximum swaps are required.

🔹 Time Complexity: O(n²)
🔹 Space Complexity: O(1)

2) Selection Sort

🔹 Idea
Repeatedly find the smallest element and place it at the beginning.

🔹 Pseudocode

procedure selectionSort(arr):
    n = length(arr)

    for i = 0 to n-1:
        minIndex = i

        for j = i+1 to n-1:
            if arr[j] < arr[minIndex]:
                minIndex = j

        swap arr[i] and arr[minIndex]

🔹 Explanation

Find the minimum element in the unsorted portion.

Swap it with the first unsorted element.

Repeat for the rest of the array.

🔹 Best Case: O(n²)

Even if already sorted, comparisons are still performed.

🔹 Worst Case: O(n²)

Reverse sorted or random array.

Always performs same number of comparisons.

🔹 Time Complexity: O(n²)
🔹 Space Complexity: O(1)

3) Insertion Sort

🔹 Idea
Build the sorted array one element at a time by inserting elements into their correct position.

🔹 Pseudocode

procedure insertionSort(arr):
    n = length(arr)

    for i = 1 to n-1:
        key = arr[i]
        j = i - 1

        while j >= 0 and arr[j] > key:
            arr[j+1] = arr[j]
            j = j - 1

        arr[j+1] = key

🔹 Explanation

Assume first element is sorted.

Take next element and insert it in correct position.

Efficient for small or nearly sorted arrays.

🔹 Best Case: O(n)

When the array is already sorted.

Only one comparison per element.

🔹 Worst Case: O(n²)

When the array is reverse sorted.

Each element shifts through the entire sorted portion.

🔹 Space Complexity: O(1)

4) Merge Sort

🔹 Idea
Divide the array into halves, sort each half, then merge them.

🔹 Pseudocode

procedure mergeSort(arr):
    if length(arr) <= 1:
        return arr

    mid = length(arr) / 2
    left = mergeSort(arr[0:mid])
    right = mergeSort(arr[mid:end])

    return merge(left, right)


procedure merge(left, right):
    result = empty list

    while left not empty AND right not empty:
        if left[0] <= right[0]:
            append left[0] to result
            remove left[0]
        else:
            append right[0] to result
            remove right[0]

    append remaining elements of left (if any)
    append remaining elements of right (if any)

    return result

🔹 Explanation

Uses divide and conquer.

Recursively splits until single elements.

Merges sorted halves.

🔹 Best Case: O(n log n)

Already sorted or random — same behavior.

🔹 Worst Case: O(n log n)

Performance remains consistent.

🔹 Space Complexity: O(n)

5) Quick Sort

🔹 Idea
Pick a pivot, move smaller elements to left and larger to right, then recursively sort both sides.

🔹 Pseudocode

procedure quickSort(arr, low, high):
    if low < high:
        pivotIndex = partition(arr, low, high)
        quickSort(arr, low, pivotIndex - 1)
        quickSort(arr, pivotIndex + 1, high)


procedure partition(arr, low, high):
    pivot = arr[high]
    i = low - 1

    for j = low to high - 1:
        if arr[j] <= pivot:
            i = i + 1
            swap arr[i] and arr[j]

    swap arr[i+1] and arr[high]
    return i + 1

🔹 Explanation

Choose a pivot.

Rearrange so:

Left side < pivot

Right side > pivot

Recursively sort both sides.

🔹 Best Case: O(n log n)

Pivot divides array into equal halves.

🔹 Worst Case: O(n²)

Pivot is always smallest or largest element.

Creates highly unbalanced partitions.

🔹 Average Case: O(n log n)
🔹 Space Complexity: O(log n)

#pragma once

#include <vector>
using namespace std;
template <class T>
int partition(vector<T> &array, int low, int high) {
    T pivot = array[high];
    int i = low-1;
    for (int j = low; j<high; j++) {
        if (array[j]<=pivot) {
            i += 1;
            //swap arr[i] and arr[j]
            T temp = array[i];
            array[i] = array[j];
            array[j] = temp;
        }
    }
    //swap arr[i+1] and arr[high]
    T temp = array[i+1];
    array[i+1] = array[high];
    array[high] = temp;
    return i+1;
}
template <class T>
void sort(vector<T> &array, int low, int high)
